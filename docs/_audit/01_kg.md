# Audit 01 — The Knowledge-Graph (KG) Layer

**Scope:** the Turtle ontologies in `src/resources/`, the two Java parsers that read them
(`OntologyArtifact.java`, `StereotypeReasoner.java`), and the exact path by which an ontology
triple becomes (i) an initial-Q penalty, (ii) a runtime soft prior, and (iii) an IV gate inside
`QLearner.java`. Every claim is cited as `path#Lstart-Lend`.

**Git state at time of audit:** branch `phase2-instant-blacklist`, last commit
`ba0303e` dated 2026-07-07 (`docs(phase2): labmon2_f2dead_lowsun results ...`). This is the
NEW phase-based era. Working tree has untracked `THESIS_PIVOT_MASTER.md`, `.node-red-lab*`
folders, and NEW-era analysis scripts — consistent with the NEW approach being current.

**Two eras (do not mix numbers):**

| Era | Domain ontology files | WoT / interaction files | State-slot registry lives in | Loaded by profiles |
|---|---|---|---|---|
| **OLD** (custom labs) | `lab-ontology.ttl`, `lab-ontology-custom2.ttl` | `interactions-lab-custom*.ttl` | separate `wot-mappings.ttl` / `wot-mappings-custom2.ttl` | `lab1`…`lab5`* custom8/custom9 etc. via `ont(["lab-ontology.ttl", …, "wot-mappings*.ttl"])` |

## Part A — the `.ttl` files

### A.0 Namespaces (identical across both eras)

`lab-ontology.ttl#L1-L15`, `building_1_trivial.ttl#L1-L13`:

```turtle
@prefix brick: <https://brickschema.org/schema/Brick#> .
@prefix elem:  <http://w3id.org/elementary#> .
@prefix qudtqk: <http://qudt.org/vocab/quantitykind/> .
@prefix sosa:  <http://www.w3.org/ns/sosa/> .
@prefix lab:   <http://example.org/was/lab#> .            # instances
@prefix ws:    <http://example.org/was/lab/stereotypes#> . # stereotype vocab
```

The design follows Ramanathan & Mayer (BuildSys '23): `elem:` (Elementary) supplies component
stereotypes and physical mechanisms; `brick:` supplies structural topology (`brick:feeds`,
`brick:isLocatedIn`, `brick:Room`, `brick:Luminaire`, `brick:Blind`); `qudtqk:` supplies quantity
kinds; `sosa:` supplies observable properties (`lab-ontology.ttl#L98-L106`).

### A.2 The core stereotype patterns: Causes vs Mediates

**Causes** (MV → DV directly, no IV; sign asserted via `elem:increases`). Lamp, OLD era
`lab-ontology.ttl#L109-L114`:

```turtle
ws:pm_incandescent_light_emission a owl:NamedIndividual, elem:PhysicalMechanism ;
    elem:hasManipulatedVariable elem:electrical_power_input ;
    elem:hasDependentVariable   elem:luminiscence ;
    elem:increases              elem:luminiscence .
```

Same lamp, NEW era `building_1_trivial.ttl#L68-L73`. Spotlight is also Causes
(`building_3_complex.ttl#L95-L99`).

**Mediates** (MV gates an IV→DV transfer; sign is state-dependent, so `elem:increases`
is deliberately omitted and `ws:ivMinRank` is asserted instead). Blind, OLD era
`lab-ontology.ttl#L118-L135`:

```turtle
ws:pm_daylight_ingress a owl:NamedIndividual, elem:PhysicalMechanism ;
    ...
    elem:hasIndependentVariable ws:outdoorIlluminance ;   # IV = sunshine (uncontrolled)
    elem:hasManipulatedVariable ws:blindApertureRatio ;   # MV = up/down (agent-controlled)
    elem:hasDependentVariable   elem:luminiscence ;        # DV = indoor lux
    ws:ivMinRank                1 ;
    elem:affectedUpstreamVariable ws:blind_light_contribution .
```

Blind, NEW era (leaner, same structure) `building_3_complex.ttl#L89-L94`:

```turtle
ws:pm_daylight_ingress a owl:NamedIndividual, elem:PhysicalMechanism ;
    elem:hasIndependentVariable ws:outdoorIlluminance ;
    elem:hasManipulatedVariable ws:blindApertureRatio ;
    elem:hasDependentVariable   elem:luminiscence ;
    ws:ivMinRank                1 .
```

The comment in the OLD base spells out the contract:
`lab-ontology.ttl#L123-L133` — "The effect direction is therefore STATE-DEPENDENT (positive only
when sunshine rank ≥ ws:ivMinRank); consequently elem:increases is intentionally NOT asserted here
— the consumer derives the sign per-state from the IV rank."

**Passive (non-actuatable) mechanism** — room accumulation, no MV, so the actuator query never
returns it: `lab-ontology.ttl#L139-L155`. In NEW self-contained labs the room is dropped entirely;
`brick:feeds` runs actuator → sensor directly (`building_3_complex.ttl#L456-L470`).

### A.5 Cross-zone coupling — `brick:feeds` and reified coupling class (NEW lab3)

Same-zone and cross-zone spill are asserted as plain `brick:feeds` arcs
(`building_3_complex.ttl#L456-L470`), and then **each arc is reified** as an
`elem:InternalConnection` tagged with a magnitude class (`building_3_complex.ttl#L475-L520`):

```turtle
ws:conn_CLz1_to_LSz2 a owl:NamedIndividual, elem:InternalConnection ;
    ws:connSource lab:CeilingLight_Z1 ; ws:connTarget lab:LightSensor_Z2 ;
    elem:hasStructuralStereotype ws:WeakOpticalCoupling .      # cross-zone spill → SECONDARY
...
ws:conn_CLz1_to_LSz1 a owl:NamedIndividual, elem:InternalConnection ;
    ws:connSource lab:CeilingLight_Z1 ; ws:connTarget lab:LightSensor_Z1 ;
    elem:hasStructuralStereotype ws:PrimaryOpticalCoupling .   # same-zone → PRIMARY
```

The two coupling stereotypes and their mechanisms are at `building_3_complex.ttl#L338-L363`.
Critically, the SECONDARY mechanism **omits any magnitude** — comment
`building_3_complex.ttl#L349-L350`: "gain/magnitude intentionally ABSENT — learned by the Q-agent
(Phase 3)." The KG asserts *structure* (which component bleeds where), never the numeric gain.

The OLD base has the same-zone + cross-zone `brick:feeds` arcs but no reification
(`lab-ontology.ttl#L690-L715`, incl. the 4 cross-zone arcs at `#L706-L715`).

### A.6 The monitor "strange fallback light" stereotype (NEW, Phase 2.5)

`building_6_monitor.ttl#L112-L128` models a monitor as a **Causes** mechanism with *multiple*
dependent variables, only one of which is illuminance:

```turtle
ws:pm_monitor_operation a owl:NamedIndividual, elem:PhysicalMechanism ;
    elem:hasManipulatedVariable ws:monitor_power_input ;
    elem:hasDependentVariable   ws:displayed_information ;   # PRIMARY output (NOT Illuminance → not actuated as a light)
    elem:hasDependentVariable   elem:luminiscence ;          # SIDE-EFFECT (Illuminance → discovered as a light action)
```

Because `discoverActuators` keeps only the DV whose quantity is `qudtqk:Illuminance`

(`building_7_dualmonitor.ttl`) puts the monitor in both zones with no spotlight; its header
(`#L37-L66`) documents the intended "reach rank 2 only, best-effort fallback" behaviour.

### A.8 `learned_*.ttl` — runtime write-back (both artifacts)

These do not exist in `src/resources/`; they are emitted at the workspace root by two artifacts.

- **`learned_stereotypes_<bool>_<profile>.ttl`** — written by `StereotypeLearner.saveLearnedStereotypes`
  (`StereotypeLearner.java#L129`). Each record is a `learned:DiscoveredEffect` with a per-slot mean
  Δ and a significance test. Example `learned_stereotypes_true_lab3.ttl#L1-L20`:
  ```turtle
  # test: |mean|/SEM > zCutoff  AND  |mean| >= minEffect  AND  n >= minSamples
  # zCutoff=3.0  minSamples=30  minEffect=0.05
  [] a learned:DiscoveredEffect ;
     learned:action <http://example.org/was#SetSpotlight> ; learned:actionValue "true"^^xsd:boolean ;
     learned:slotIndex "0"^^xsd:int ; learned:meanDelta "1.4054"^^xsd:double ;
     learned:zScore "10.28"^^xsd:double ; learned:samples "37"^^xsd:int .
  ```
- **`learned_dynamics_<bool>_<profile>.ttl`** — written by `DynamicsLearner.saveLearnedDynamics`
  (`DynamicsLearner.java#L177-L224`). Each record is a `learned:ResponseDynamic` carrying the
  *learned magnitude* of `ws:responseDelay`. Example `learned_dynamics_true_lab2_slow.ttl#L1-L18`:
  ```turtle
  # secondsPerTick=5.0  minSamples=3  instantThresholdSec=10.0
  [] a learned:ResponseDynamic ;
     learned:action <http://example.org/was#SetZ1Blinds> ; learned:actionValue "true"^^xsd:boolean ;
     ws:responseDelay "60.0000"^^xsd:decimal ; ws:responseDelayTicks "12"^^xsd:integer ;
     ws:responseDelaySamples "3"^^xsd:integer ; learned:responseClass ws:DelayedResponse .
  ```
  (The blind delay of 60 s = 12 ticks matches the header's `BLIND_DELAY_TICKS = 12`,
  `building_2_slow.ttl#L30`.)

## Part B — how the parsers read the TTL

### B.1 `OntologyArtifact.java` (CArtAgO artifact)

- **Load:** `init(Object[] ttlResourcePaths)` reads each classpath TTL into a single Jena
  `OWL_MEM_MICRO_RULE_INF` `OntModel` (`OntologyArtifact.java#L166-L179`). This is the model on
  which the `owl:equivalentProperty brick:feeds ≡ elem:feeds` bridge (`building_3_complex.ttl#L43`)
  is materialised by the micro rule reasoner.
- **Four SPARQL queries** (all use the `PREFIXES` block `OntologyArtifact.java#L55-L63`):
  - `DISCOVER_ZONES_QUERY` — every `lab:Workstation` + `ws:zoneIndex`, ordered
    (`#L77-L86`).
  - `DISCOVER_ZONE_QUANTITY_QUERY` — the shared quantity that a zone's sensor senses AND an
    actuator produces, filtered to `qudtqk:Illuminance` (`#L91-L111`).
  - `ZONE_COMPONENTS_QUERY` — actuatable components in a zone whose mechanism produces the target
    DV, with `OPTIONAL` IV/WoT bindings (`#L116-L136`).
  - `DISCRETIZATION_BOUNDS_QUERY` — reads `ws:rankBound_1/2/3` for a process variable
    (`#L140-L143`).
- **`getDiscretizationBounds`** (`#L285-L312`) runs that query and, if the triples are absent,
  logs a warning and **falls back to `{50.0, 100.0, 300.0}`** (`#L309-L311`). Because every current
  `building_*.ttl` and the OLD base actually assert the bounds on `ws:sensedIlluminance`, the
  fallback is a safety net, not the live path.

### B.2 `StereotypeReasoner.java` (plain helper owned by `QLearner`)

- **`ActionInfo`** is the per-action record (`StereotypeReasoner.java#L47-L70`): `hasIV`,
  `ivStateVecIndex`, `ivMinRank` (default 1), `affectedZones`, `energyCost`, `stateVecBitIndex`,
  `expectedBitValue`.
- **`ACTUATOR_DISCOVERY_QUERY`** (`#L114-L143`) is the heart of discovery. It requires
  component → `elem:hasBehavioralStereotype` → mechanism with an `elem:hasManipulatedVariable`, a DV
  filtered by `FILTER EXISTS { ?dv elem:hasQuantity qudtqk:Illuminance }` (`#L129`), joined to
  `elem:hasComponentAction`/`ws:actionValue`. IV, `ws:ivMinRank`, WoT types and `ws:energyCost`
  are all `OPTIONAL` (`#L131-L137`). One result row = one (component, ON/OFF).
- **`discoverActuators`** (`#L547-L651`) merges rows by `wotAction + "|" + actionValue`, and sets
  (`#L568-L578`):
  ```java
  ai.hasIV          = actionValue && hasIV;          // IV only matters for the ON action
  ai.ivStateVecIndex= (actionValue && hasIV) ? sunshineIndex : -1;
  ai.ivMinRank      = (actionValue && hasIV) ? ivMinRank : 1;
  ai.expectedBitValue = actionValue ? 1 : 0;
  ```
  A synthetic `DO_NOTHING` is appended (`#L611-L625`), and the method **fails loud** with
  `IllegalStateException` if only `DO_NOTHING` was produced (`#L644-L650`).
- **`CROSS_ZONE_FEEDS_QUERY`** (`#L145-L167`) walks `brick:feeds` from an actuator to a sensor in a
  *different* zone (`FILTER (?sourceZoneIdx != ?targetZoneIdx)`), and `OPTIONAL`-reads the reified
  coupling stereotype (`#L159-L165`) so `discoverCrossZoneFeeds` (`#L704`) can mark each
  `CrossZoneEffect` `PRIMARY` or `SECONDARY` (`ws:WeakOpticalCoupling ⇒ SECONDARY`).
- **`POWER_GATE_QUERY`** (`#L179-L185`) reads `ws:powerGates` arcs (lab4) and rebinds the gated
  lamp's ON action onto the plug's state slot, *reusing* the IV machinery (`discoverPowerGates`
  `#L664`).

## Part C — from ontology triple to Q-learning behaviour

Three distinct surfaces. **All current default magnitudes below are the NEW-era values in the
code as committed; the OLD memory-note values (scale 5.0, floor 0.1, priors −5/−25) are stale.**

### C.1 (i) Initial-Q penalties — `getInitPenaltyForZone`

`QLearner.initWithStereotypes` writes a penalty into every `(zone, state, action)` cell at
construction (`QLearner.java#L477-L486`):

```java
qTables[z][s][a] = reasoner.getInitPenaltyForZone(fullSv, a, z, goal);
```

`getInitPenaltyForZone` (`StereotypeReasoner.java#L1069-L1167`) applies six rules, then multiplies
by `INIT_PENALTY_SCALE` (default **0.5**, `#L288-L290`):

| Rule | Condition | Raw value | Cite |
|---|---|---|---|
| 1 Redundancy | actuator bit already == expected | `-100 * scale` (early return) | `#L1074-L1079` |
| 2 **IV gate (Mediates)** | `ai.hasIV && ai.wotValue && stateVec[ivStateVecIndex] < ai.ivMinRank` | `-100` | `#L1085-L1091` |
| 3 Cross-zone overshoot | action spills into this zone and zone ≥ goal | `-50` | `#L1096-L1107` |
| 4 Shared-actuator at-goal | multi-zone ON action while zone ≥ goal | `-75` | `#L1110-L1116` |
| 5 **Constructive bonus** | no well fired, ON action affects zone, `gap>0`, IV OK | `+INIT_BONUS_MAG(15) * gap * scale` | `#L1118-L1136` |
| 6 Cross-zone bonus | `-Dstereo.crossZoneBonus>0`, SECONDARY spill, `gap>0` | `+crossZoneBonus * gap * scale` | `#L1138-L1160` |

Rule 2 is the **only** consumer of the static `ws:ivMinRank` triple. Rule 5 (the constructive
optimistic bonus) is a NEW-era addition: comment `#L1118-L1130` explains the legacy prior was
penalty-only and could not point the agent *toward* a helpful action.

### C.2 (ii) Runtime soft priors — `getActionPriors` + `greedyAction`

`greedyAction` (`QLearner.java#L2539-L2620`) fetches priors and adds a decayed, faded bias to
combined Q:

```java
priors = reasoner.getActionPriors(sv);                        // #L2549
double w = 1.0 - frac * (1.0 - PRIOR_DECAY_FLOOR);            // linear decay, #L2558-L2561
priorWeight = STEREO_PRIOR_SCALE * w;                          // #L2562
...
effectivePrior = priorWeight * priors[a] * calMul * cellMul;  // #L2597
double q = combinedQ(stateIdx, a) + effectivePrior;           // #L2598
```

`getActionPriors` (`StereotypeReasoner.java#L1029-L1064`) returns per action:
- `0.0` for `DO_NOTHING`;
- `-PRIOR_REDUNDANT_MAG` (default **1.0**) if redundant (`#L1058`);
- `-PRIOR_IV_UNSAT_MAG` (default **5.0**) if `ai.wotValue && !isIVSatisfied(...)` (`#L1060`);
- `0.0` otherwise.

> Note: the Javadoc above the method still says "−5.0 / −25.0" (`#L1019-L1027`) — **stale**; the
> code returns the `-PRIOR_*_MAG` constants (`StereotypeReasoner.java#L253-L272`).

Relevant `QLearner` constants (current defaults):
- `STEREO_PRIOR_SCALE = 1.0` (`QLearner.java#L67`; was 5.0).
- `PRIOR_DECAY_FLOOR = 0.0` (`#L94`; was 0.1 → prior now decays to **zero**, not a permanent floor).
- `priorDecayEpisodes` auto = `num_episodes/4`, default 2500 (`#L86-L89`).
- `PRIOR_FADE_VISITS = 25` (`#L100`): `cellMul = min(1, 25/visits[s][a])` fades the prior out on
  any cell visited ≥ 25 times (`#L2585-L2593`).
- `calMul` is the adaptive-trust multiplier keyed by sun bucket (`#L2578-L2584`).
- `ENERGY_PRIOR_WEIGHT = 0.0` (`#L80`): a separate, **non-fading** `-weight * energyCost` term
  applied at `#L2604-L2611`, only when `ws:energyCost > 0` (lab5).

### C.3 (iii) IV gating — `isIVSatisfied` / `getLearnedIVMinRank`

Both live in `StereotypeReasoner.java`:

- **`isIVSatisfied(stateVec, actionIdx)`** (`#L909-L923`): if the action has no IV, returns `true`.
  Otherwise it looks at the *learned* effectiveness at the current IV rank:
  ```java
  int ivRank = stateVec[ai.ivStateVecIndex];
  if (ivTrialCount[actionIdx][ivRank] >= IV_MIN_SAMPLES) {           // default 10, #L223
      double eff = (double) ivSuccessCount[...][ivRank] / ivTrialCount[...][ivRank];
      return eff >= IV_EFFECTIVENESS_THRESHOLD;                       // default 0.05, #L235
  }
  return true;   // under-sampled → optimistic, allow exploration
  ```
  So the gate is driven by **learned statistics**, not by the static `ws:ivMinRank` — the static
  triple only drives Rule 2 above. `IV_MIN_SAMPLES = 10` (`#L223-L224`),
  `IV_EFFECTIVENESS_THRESHOLD = 0.05` (`#L235-L236`, lowered from 0.10 per audit note in-source).
- **`getLearnedIVMinRank(actionIdx)`** (`#L976-L993`): scans ranks 0→3, returns the first rank
  whose learned effectiveness ≥ threshold (with `IV_MIN_SAMPLES` observed), else the first
  under-sampled rank (optimistic), else `4` ("never effective"). Comment marks it **diagnostic
  only — not invoked by QLearner during action selection** (`#L971-L974`); it is read by
  `saveIVStats`.

### C.4 The Mediates(blind, sunshine) threshold-learning loop

The threshold the blind must learn (the sunshine level above which raising the blind helps) is
**not** a value in the KG — the KG asserts only `ws:ivMinRank 1` (structure) and leaves the
per-rank effectiveness to be measured. The full loop:

1. **Static prior (cold start).** `ws:ivMinRank 1` on `pm_daylight_ingress`
   (`building_3_complex.ttl#L94`) → parsed into `ai.ivMinRank`
   (`StereotypeReasoner.java#L568-L578`) → Rule 2 stamps `-100 * 0.5` into every blind-ON cell whose
   `stateVec[sunshineIndex] < 1` at construction (`#L1085-L1091`). This discourages opening the
   blind when sunshine rank is 0, before any experience.
2. **Observation.** After every step, `QLearner` calls
   `reasoner.recordActionOutcome(action, prevSv, nextSv)` (`QLearner.java#L621`).
   `recordActionOutcome` (`StereotypeReasoner.java#L935-L966`) — only for activation actions with an
   IV — bins by the *previous* sunshine rank, increments `ivTrialCount[a][ivRank]`, and increments
   `ivSuccessCount[a][ivRank]` iff any affected zone's **level rank strictly increased**
   (`#L951-L959`). "Blind at sun rank 3 usually moves the rank; at sun rank 0 it never does" is thus
   learned empirically, per rank.
3. **Runtime gate.** Once ≥ `IV_MIN_SAMPLES` samples exist at a rank, `isIVSatisfied`
   (`#L913-L918`) returns whether learned effectiveness ≥ 0.05, which flips the soft prior in
   `getActionPriors` between `0.0` and `-PRIOR_IV_UNSAT_MAG` (`#L1060`) — i.e. the agent stops being
   nudged away from the blind at exactly the sun ranks where it has observed the blind to work.
4. **Effectiveness feeds greedy choice through the soft-prior channel only** (Part C.2); the
   *learned numeric threshold* surfaced by `getLearnedIVMinRank` is diagnostic (written to
   `iv_stats_*.json` via `saveIVStats` `#L1180-L1197`, e.g. `iv_stats_stereotypes_true_lab3.json`).

**Persistence / train→bench hand-off:** `saveIVStats` writes the per-rank trial/success matrices
(`#L1180-L1197`); `loadIVStats` restores them (`#L1207-L1240`), so the blind's learned sunshine
threshold carries from the training agent into the benchmark agent.
